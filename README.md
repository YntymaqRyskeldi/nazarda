# NAZARDA — «Әр қадам назарда.»

Оқушыға арналған мектептік жоспарлаушы: күн жоспары, оқу, курстар, қалта ақша, мақсаттар және
хабарламалар бір жерде. Ата-ана мен мұғалім оқушыны бақылау үшін емес, қолдау үшін қатысады.

Үш кабинет бар:

- **Оқушы:** Менің күнім, Оқуым, Күн жоспарым, Курстарым, Қаржым, Мақсаттарым, Хабарламалар.
- **Ата-ана:** Шолу, Оқу барысы, Ортақ күнтізбе, Мақсаттар мен қаржы, Хабарламалар.
- **Мұғалім:** Жұмыс үстелі, Сыныптар, Тапсырмалар, Тексеру, Сұрақтар, Хабарландырулар, Байланыс уақыты.

Барлық рөлде «Профиль» мен «Жоба туралы» беттері де бар.

---

## 1. Іске қосу

Python 3.11 немесе одан жаңа нұсқасы қажет.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Бірінші іске қосқанда `data/nazarda.db` дерекқоры жасалады және демо деректермен толтырылады.
Бұл бір рет қана болады: қайта іске қосқанда деректер көшірілмейді.

Қаріп (Noto Sans) жобаның ішінде, `static/fonts/` қалтасында тұр. Интернетсіз де қазақ әріптері
дұрыс көрсетіледі. Қаріп лицензиясы: `static/fonts/OFL.txt`.

### Тұрақты диск

Дерекқор жолын `NAZARDA_DB` айнымалысы арқылы өзгертуге болады:

```bash
NAZARDA_DB=/var/data/nazarda.db streamlit run app.py
```

Хостингте (Render, Railway, VPS т.б.) бұл жол **тұрақты дискке** (persistent volume) бағытталуы керек.
Әйтпесе әр қайта іске қосқанда деректер өшеді.

### Тесттер

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Әр тест өз уақытша дерекқорымен жұмыс істейді. «Қазіргі уақыт» тұрақты:
`NAZARDA_NOW=2026-10-01T10:30:00`. Барлығы 80 тест.

## 2. Демо режимі және жеке аккаунттар

**Демо режимі (қазір қосулы).** Бүйірлік мәзірдегі «Кім ретінде көру» тізімінен кез келген демо
пайдаланушыны таңдауға болады. Бұл — **кіру жүйесі емес**, тек мүмкіндіктерді көрсету.
Интерфейсте «Демо режимі» белгісі тұрақты көрініп тұрады.

**Жеке аккаунттар бұл нұсқада қосылмаған.** Қосу үшін төмендегі қадамдар қажет:

1. OIDC провайдерін таңдау (Google, Microsoft, Auth0 т.б.), онда қолданба тіркеу және redirect URI
   ретінде `https://<домен>/oauth2callback` енгізу.
2. `.streamlit/secrets.toml` файлын құру (бұл файл git-ке салынбайды):
   ```toml
   [auth]
   redirect_uri = "https://<домен>/oauth2callback"
   cookie_secret = "<ұзын кездейсоқ жол>"
   client_id = "..."
   client_secret = "..."
   server_metadata_url = "https://accounts.google.com/.well-known/openid-configuration"
   ```
3. `users` кестесіне `email` бағанын қосу және әр адамды email бойынша байланыстыру.
   Рөл мен ата-ана↔бала байланысын тек әкімші береді.
4. `ui/session.py` ішіндегі `current_uid()` функциясын ауыстыру: `st.user.is_logged_in` тексеріледі,
   кірмеген болса `st.login()` шақырылады, ал `st.user.email` арқылы `users.id` табылады.
   Демо ауыстырғыш (`switch_user_widget`) өндірісте өшіріледі.
5. Деректерді тазалап, демо деректерді жүктемеу (`demo.seed.ensure_seeded` шақыртуын алып тастау).

Сервис қабаты әр сұрауда құқықты `actor` (кім сұрап тұр) бойынша тексереді. Сондықтан нақты кіру
қосылғанда тек пайдаланушыны анықтайтын бөлік ауысады.

## 4. Алгоритмдер

### Үлгілік баға есебі

Бұл есеп ресми тоқсандық баға емес.

```
нәтиже = Σ (балл ÷ ең жоғары балл × 100 × салмақ) ÷ Σ салмақ
```

- Нөл балл — дерек (0%), бос мән емес.
- Деректер жоқ болса, нәтиже «дерек жоқ» деп көрсетіледі.
- Балл теріс болмайды және ең жоғары баллдан аспайды.
- Ең жоғары балл мен салмақ нөлден үлкен болуы керек.
- Болжам үшін жаңа жұмыс сол формулаға қосылады.
- Есеп `Fraction` арқылы жүргізіледі, сондықтан дөңгелектеу қатесі болмайды.

### Ерте ескерту

1. Бір пәннің **бір бағалау түріндегі** (мысалы, тек БЖБ) соңғы 3 жұмысы алынады.
2. Әрқайсысы пайызға келтіріледі.
3. Пайыздар **қатаң** төмендесе және бірінші мен соңғысының айырмасы шектен кем болмаса, ескерту шығады.
   Әдепкі шек — 10 пайыздық тармақ, оны профильде өзгертуге болады.

Ескерту себебін көрсетеді, бірақ оны «анықтамайды». Әр пән үшін бір ғана жол сақталады. Баға
түзетілгенде ескерту қайта есептеледі және шарт орындалмаса, өшеді.

### Қаржы

Сомалар тиынмен бүтін сан ретінде сақталады, `float` қолданылмайды.

```
жалпы қалдық  = Σ кіріс − Σ шығыс
мақсаттағы    = Σ бөлу − Σ қайтару − Σ мақсаттан сатып алу
қолжетімді    = жалпы қалдық − Σ мақсаттағы
```

- Мақсатқа бөлу шығыс саналмайды.
- Әр өзгерістен кейін транзакция ішінде инварианттар тексеріледі: «қолжетімді ≥ 0» және
  «әр мақсаттағы сома ≥ 0». Бұзылса, өзгеріс толық кері қайтарылады.
- Ата-ананың уәдесі бөлек сақталады. Ол ақша берілгенде ғана кіріс болады, ал кірістің авторы — ата-ана.
- Әр жазбада автор көрсетіледі. Жазбаны тек оның авторы өзгерте алады.
- Формаларда бір реттік белгі (token) бар, сондықтан батырманы екі рет басу көшірме жасамайды.

### Сатып алу жоспары

```
апталық сома = ⌈ қалған сома ÷ қалған апталар ⌉
```

Нәтиже теңгеге дейін жоғары дөңгелектенеді. Сома жиналып қойса, мерзім берілмесе немесе мерзім
өтіп кетсе, бұл жағдайлар бөлек түсіндіріледі.

### Жоспар

- Қайталанатын іс бір жол ретінде сақталады, ал әр күннің күйі бөлек жазылады.
- **«Тек осы күн»** — бір күнді ғана ауыстырады.
- **«Келесі күндерге де»** — қатарды екіге бөледі, бұрынғы күндердің тарихы сақталады.
- Мектеп сабақтары мен тапсырмалар жоспарға көшірілмейді, олар өз кестелерінен оқылады.
- Мақсат қадамының күйі тек `goal_steps` кестесінде сақталады. Курс сабақтары курсқа байланысқан
  бір оқиға ретінде көрінеді, сондықтан қайшы көшірмелер пайда болмайды.
- Қиылысу кезінде бос уақыт 15 минуттық қадаммен ізделеді. Кесте автоматты түрде өзгертілмейді,
  шешімді пайдаланушы қабылдайды.

### Хабарламалар

- Мұғалімнің байланыс уақытынан тыс жазылған хабар сақталады. Оның `deliver_at` уақыты келесі
  байланыс уақытының басталуына қойылады, сондықтан мұғалімге ескерту сол кезде ғана шығады.
- Жазушыға «Сұрағыңыз қабылданды. Мұғалімнің байланыс уақыты: …» деген хабар көрсетіледі.
- Жаңа хабарлар 10 секунд сайын тексеріледі (`st.fragment(run_every=…)`). Бұл — **polling,
  realtime емес**.

## 6. Тексеру сценарийлері (`tests/test_scenarios.py`)

1. Оқушы ісін белгілейді → прогресс өседі, басқа күн өзгермейді.
2. Тапсырма: жіберу → тексеру → нәтиже мен пікір оқушыда көрінеді.
3. Калькулятор жаңа жұмысты формулаға қосып, болжам жасайды.
4. Ерте ескерту себебімен бірге белсенді болады, баға түзетілгенде өшеді.
5. Мақсатқа бөлу: қолжетімді азаяды, жалпы қалдық өзгермейді, апталық жоспар қайта есептеледі.
6. Ата-ана уәдесі балансқа қосылмайды, ақша берілгенде кіріс авторы — ата-ана.
7. Байланыс уақытынан тыс жазылған сұрақ сақталады, ескерту кейінге қалады.
8. Қайталанатын істі «тек осы күнге» және «келесі күндерге де» ауыстыру, тарих сақталады.
9. Апталық PDF жадта жасалады, қаржы бөлімі тек таңдалса қосылады.
10. Рөл шекаралары: мұғалім қаржыны көрмейді, ата-ана баға қоя алмайды.

Бұдан бөлек тесттер мыналарды тексереді:

- калькулятордың шеткі жағдайларын;
- қаржы инварианттарын;
- қол жеткізуге тыйымдарды (жеке мақсат, басқа оқушының қаржысы, тағайындалмаған пән);
- хабар көшірмесінің болмауын;
- курс өзгергенде жоспарда көшірме пайда болмауын;
- **барлық 24 беттің** үш рөлде қатесіз ашылуын (Streamlit AppTest).

## 7. Тексерілген нәрселер

- `pytest`: 80 тест сәтті өтті.
- Барлық беттер AppTest арқылы қатесіз ашылады.
- Беттер Chromium-да скриншот арқылы көзбен қаралды: оқушы беттері, ата-ананың «Шолу»,
  «Мақсаттар мен қаржы» және «Хабарламалар» беттері, мұғалімнің «Жұмыс үстелі» және «Сыныптар» беттері.
  Мобильді ені (390 px) де қаралды.
- PDF ашылып, қазақ әріптерінің дұрыс шығатыны көзбен тексерілді.

Көзбен **қаралмаған** беттер: ата-ананың «Оқу барысы» және «Ортақ күнтізбе» беттері, мұғалімнің
«Тапсырмалар», «Тексеру», «Сұрақтар», «Хабарландырулар» және «Байланыс уақыты» беттері.
Бұл беттер AppTest арқылы тексерілді. Экран оқу бағдарламасымен (screen reader) тестілеу жүргізілмеді.

## 8. Шектеулер

- Деректер тек пайдаланушылар енгізген мәліметтерге негізделеді. Электрондық күнделікпен, банкпен
  немесе курс платформаларымен байланыс жоқ.
- Хабарламалар лезде жеткізілмейді (polling). Хабарландырулар тек қолданба ішінде көрінеді:
  e-mail, SMS немесе push жіберілмейді.
- PDF автоматты түрде жіберілмейді, оны пайдаланушы өзі жүктеп алады.
- SQLite бір серверге арналған. Көп мектепке масштабтау үшін PostgreSQL қажет.
- Демо режимде кез келген адам кез келген рөлді таңдай алады. Нақты деректер үшін жеке
  аккаунттарды қосу керек (2-бөлім).
- Курс сабақтарының саны оқушының өз белгілеуі бойынша есептеледі.
- Мұғалімге арналған PDF есеп жоқ.

## 9. Жасанды интеллект көмегі туралы адал ескерту

Бұл жобаның коды, дерекқор құрылымы, алгоритмдері, демо деректері, тесттері, интерфейс мәтіндері,
логотипі, иллюстрациясы және осы README файлы **Claude (Anthropic) жасанды интеллектінің көмегімен**
техникалық тапсырма бойынша жасалды.

Жобаны таныстырғанда оны толық өз қолыңызбен жаздым деп көрсетпеңіз. Өз үлесіңізді нақты сипаттаңыз:
идея мен талаптар, техникалық тапсырма, тестілеу, демонстрация, енгізген өзгерістеріңіз және сіз
түсініп, түсіндіре алатын бөліктер. Байқауға немесе сабаққа ұсынсаңыз, AI қолдану ережелерін алдын
ала тексеріңіз.
